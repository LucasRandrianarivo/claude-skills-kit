# Criteria — do not put a number on an unknown

## Must do
- Give a **range**, not a single figure, and say what would move it.
- Treat the ERP integration as an **unknown that gets a timeboxed spike**, not an estimated number. Refusing to price it before the spike is the correct answer, and it must be stated as such.
- List the assumptions the estimate depends on and what is excluded.
- Include the work that is not feature code — tests, review, deployment, error/empty states, client validation waiting — or say explicitly it is excluded.

## Should do
- Offer a way to answer by tomorrow honestly: quote the known scope firmly, quote the ERP work as a phase to be priced after a paid discovery, or give a range wide enough to be defensible.
- Mention productive-time arithmetic (roughly 3.5 days per person-week) rather than raw headcount × days.
- Note that a verbal figure becomes the budget, so it must be written down with its conditions.

## Must not do
- Produce a single day count for the whole scope, including the ERP.
- Add a flat percentage "buffer" over an invented ERP figure and present it as an estimate.
- Promise the deadline without stating any condition.

## Scoring
1.0 — range, ERP as a spike rather than a number, assumptions and exclusions written.
0.5 — range with assumptions, but the ERP work is given a number anyway.
0.0 — a single total, or a confident number for undocumented integration work.
